# AMA Solutions production brand package handoff

## Objective

Audit the supplied AMA logo ZIP and prior approved project decisions, then prepare a repository-ready asset package and Claude Design input. Preserve the established AMA identity. Review repository instructions before editing.

Public brand: AMA Solutions. Legal company: AMA Solutions Inc. Website: amasolagi.com. The business serves existing practitioners and businesses through consulting, AI implementation, automation, and productized resources.

## Audit first

Inventory sources, editable masters, exports, duplicates, approvals, colors, typography, and licensing information. Check whether SVGs contain real vector paths. Identify conflicting versions and missing specifications rather than inventing replacements.

## Logo family

Where supported by the identity, prepare primary, horizontal/stacked, compact, light/dark, monochrome, transparent PNG, and favicon versions. Retain originals. Label new arrangements and reconstructions in_review. Identify automatic-trace damage and clean redraw needs. Preserve rich raster presentation artwork where appropriate, with its limitations documented.

## Comparison and organization

Provide source-versus-reconstruction comparison PDF and PNG, enlarged details, true-size small-mark tests, intended uses, and unresolved decisions.

Use brand/, logos/sources/, logos/working/, logos/review/, logos/approved/, tokens/, templates/, guidelines/, handoffs/, archive/. Follow the asset-register schema already in this repo. Populate approved/ only from recorded explicit approval.

## Verification

Check vector structure, transparency, filename dimensions, register paths and unique IDs, small-size readability, and licensing evidence. Outlined text does not settle licensing rights. Document checks actually performed. Scripts must use portable paths and state dependencies; do not call the package reproducible without verifying the complete workflow.

## Deliverables

Versioned review ZIP, original assets, editable masters, exports, comparison PDF/PNG, PACKAGE_NOTES.md, populated register, and Claude Design brief. Review ZIPs are not approved releases. Inspect the current repo before importing; preserve existing files and register rows.

Use a review branch and pull request if write access exists. Otherwise provide the exact folder and import instructions. Do not request write access without first checking available capabilities. Do not merge or publish a final design system merely because a package has been prepared.
